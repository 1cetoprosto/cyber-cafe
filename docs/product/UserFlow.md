# Документація User Flow - TrackMyCafe

Цей документ описує основні сценарії використання додатку **TrackMyCafe**. Він призначений для користувачів, щоб зрозуміти логіку роботи, та для розробників, щоб мати еталонний сценарій тестування та розвитку функціоналу.

---

## 1. Вступ
**TrackMyCafe** — це додаток для управління невеликою кав'ярнею. Він дозволяє вести облік продажів (доходів), закупівель та інших витрат, керувати меню та отримувати базову аналітику.

Зовнішнє позиціонування і канонічні тексти (App Store, онбординг, paywall): [POSITIONING_AND_COPY.md](POSITIONING_AND_COPY.md).

---

## 2. Початок роботи (Getting Started)

### Встановлення та Перший запуск
Після встановлення додатку користувач потрапляє на екран авторизації.

1.  **Реєстрація (Sign Up):**
    *   Якщо у вас ще немає акаунту, натисніть "Sign Up".
    *   Введіть Email, Пароль та підтвердження пароля.
    *   Після успішної реєстрації ви автоматично увійдете в систему.

2.  **Вхід (Sign In):**
    *   Використовуйте Email та Пароль.
    *   **Біометрія:** Після першого входу можна увімкнути FaceID/TouchID в налаштуваннях для швидкого доступу.

3.  **Маркетинговий onboarding (до логіну):**
    *   3 слайди «чек → витрати → що залишилось» + trial/paywall (див. [POSITIONING_AND_COPY.md](POSITIONING_AND_COPY.md)).

4.  **Guided setup після логіну (лише owner / administrator, порожня кав’ярня):**
    *   Авто-засівання демо-даних **вимкнено**.
    *   Wizard: **профіль закладу** (склад так/ні + схема чека + category-first) → меню (2–3 товари) → перший чек → **грошова** витрата (copy залежить від режиму складу) → «що залишилось» → Home.
    *   Якщо склад **вимкнено** — закупки в грошах як opex (явно сказано, що це не залишки). Якщо **увімкнено** — витрата лише каса (світло/оренда за день); закупівлю інгредієнтів — пізніше в Settings → Ingredients.
    *   Створюється категорія «Меню» / «Menu» і один тип чека «Чек» / «Receipt» (при продажі або skip кроку чека).
    *   Прапорці per-cafe: `hasCompletedFirstRunSetup`, `hasCompletedOperatingPreferences`. Якщо меню вже є, але профіль (склад/чеки) ще не підтверджували — показується короткий preferences-only майстер.
    *   На кроці «що залишилось» — tip про масштаб (один чек vs місячна витрата).
    *   Після wizard на Home — картка «як користуватись далі» під плашкою прибутку, **лише якщо прибуток &lt; 0** (і поки не dismissed); dismiss → `hasDismissedPostSetupInsight` (per-cafe).
    *   Staff / waiter цей гайд **не** бачать.
    *   In-app coach marks (Instructions) **вимкнені** (`OnboardingManager.areCoachMarksEnabled = false`); пункт «Показати підказки знову» в Settings прихований.

5.  **Demo seed для скрінів (DEBUG):**
    *   Settings → Seed Test Data / floating «Видалити демо» працюють як раніше після **ручного** seed (App Store screenshots). У Prod/Beta авто-seed немає.

## 3. Покроковий сценарій налаштування (Setup Workflow)

### Швидкий first-win (рекомендовано новому власнику)
Після Sign Up / першого входу в `MainTabBarController` — guided setup (див. §2 п.4). Дані пишуться в Firestore через Domain-сервіси; на Home з’являються Sales / Costs / Net на **своїх** цифрах плюс одноразова картка зі звичкою «продажі → витрати → що лишилось». У Settings ключові опції мають footer секції та/або «і» з поясненням впливу на роботу додатку.

### Повне налаштування меню (Settings → Price List)
Щоб розширити меню поза wizard:

1.  Перейдіть на вкладку **Settings**.
2.  Оберіть пункт **Price List** (Прайс-лист).
3.  Натисніть **"+"** (верхній правий кут).
4.  Заповніть форму:
    *   **Name:** Назва товару (наприклад, "Капучино").
    *   **Price:** Ціна продажу.
5.  Натисніть **Save**.

### Налаштування Інгредієнтів (Settings → Ingredients) *[Опціонально]*
Якщо ви хочете вести складський облік (не частина first-run wizard).

1.  Перейдіть в **Settings -> Ingredients**.
2.  Додайте інгредієнти (наприклад, "Молоко", "Кава в зернах", "Цукор").
3.  Прив'яжіть інгредієнти до товарів через recipe/composition.
4.  Глобальне налаштування **Track Ingredients** визначає, чи продажі автоматично змінюють склад.

## 4. Щоденна робота (Daily Operations)

### Продажі та Замовлення (Таб 2 — “Доходи”, v1.0.0)
Робоче місце касира.

1.  Перейдіть на вкладку **Доходи**.
2.  Оберіть режим **“Новий чек”** для POS або **“Історія”** для перегляду продажів.
3.  У **Новому чеку**:
    *   Оберіть товари з меню (сітка).
    *   Змініть кількість за потреби.
    *   Підтвердіть збереження — продаж зафіксується, а COGS буде зафіксований як історичний snapshot.
    *   Якщо `Track Ingredients = On`, склад оновиться автоматично за рецептом.
    *   Якщо `Track Ingredients = Off`, продаж не змінює склад, але recipe/composition може зберігатись для подальшого вмикання обліку.

### Склад та Витрати (Таб 3 — “Витрати”, v1.0.0)
Операції зі складом та операційними витратами.

**Склад** (внутрішній Segmented: Залишки / Закупівлі / Інвентаризація)
1.  **Залишки:** переглядайте `stockQty` та `avgCost`, коригуйте вручну при інвентаризації.
2.  **Закупівлі:** натисніть **"+"**, оберіть інгредієнт, кількість та ціну — збережіть; склад і середня ціна оновляться.
3.  **Інвентаризація:** у версії 1.0.0 доступні ручні коригування залишків з причиною. Повноцінний режим пакетної інвентаризації з журналом `InventoryAdjustment` планується додати в наступних версіях.

**Витрати (Opex)**
1.  Оберіть режим **Витрати**.
2.  Натисніть **"+"**, вкажіть суму, дату та примітку — збережіть.
3.  Витрата миттєво вплине на узагальнені показники прибутку/витрат на дашборді. Детальний P&L із рознесенням по COGS буде доступний у майбутніх релізах.

## 5. Аналітика (Home Dashboard)

У версії **1.0.0** вкладка **Home** показує спрощену зведену інформацію:
*   Основні суми за період (дохід, витрати) та останні транзакції.
*   Базові попередження по складу (за наявності).
*   Швидкі дії для переходу до основних розділів.

У наступних версіях (1.1.0+) дашборд буде розширено до повноцінного фінансового огляду:
*   Показники `Sales`, `COGS`, `Opex`, `Gross/Net Profit` за обраний період.
*   Залишок готівка/картка.
*   Детальні попередження складу (низькі/негативні залишки) та поглиблена аналітика.
*   Reports Hub буде використовувати ті самі агрегати, що й Home, без окремого дублювання формул у UI.

## 6. Технічні нотатки для розробників

### Приховані можливості (Hidden Features)
В коді присутній функціонал, який наразі **вимкнений** (закоментований) в інтерфейсі, але готовий до впровадження:

*   **Staff Management (Управління персоналом):**
    *   Додавання співробітників (Technicians).
    *   Ролі: Waiter, Administrator.
    *   Логіка: `StaffCategoriesController`, `TechniciansListController`.
    *   *Як активувати:* Розкоментувати виклик у `SettingListViewController`.

### Структура даних
*   Основні дані зберігаються в **Firebase Firestore** (єдине сховище, офлайн — через Firebase cache).
